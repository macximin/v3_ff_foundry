# Web GPT Pro 캐논별 Arc 멀티세션 운영 템플릿

상태: owner-confirmed operating template

확정일: 2026-07-26

범위: v3 Firefly Foundry의 기존 캐논 작품별 Story Plan·B-Rail 페이싱 보강

권위: 이 문서는 실행 템플릿이다. 그 자체로 작품 캐논, 원고 승인, Storyyard 전송을 만들지 않는다.

## 1. 모델과 역할

- 총괄 세션: Codex Desktop `gpt-5.6-sol`, 빠름.
- 작품별 상주 세션: 캐논 하나당 정확히 하나, Codex Desktop `gpt-5.6-terra`, 중간.
- 생산자: Web GPT Pro.
- 작품별 세션은 자료 선별, 패킷 조립, Web GPT Pro 운반, 응답 보존, BR1 준비를 맡는다.
- BR0는 Story Plan을 보지 않은 새 블라인드 컨텍스트에서 수행한다.
- 캐논 승격은 owner 승인 뒤에만 가능하다.

작품별 세션은 다른 작품의 계획·원고·브라우저 탭을 수정하거나 대신 판단하지 않는다.

## 2. 입력 패킷

Web GPT Pro의 작품별 독립 채팅에 다음 정확본만 첨부한다.

1. Google Drive 원문 라이브러리에서 선별한 유사 성공작 3개
2. 현재 `owner_approved` 원고 정확본
3. 현재 Narrative State
4. `living_spine.md`
5. `anchor_rail.md`
6. `arc_route_rail.md`
7. `rolling_corridor.md`
8. 이 문서의 페이싱·조판 계약

과거 후보, 폐기 revision, 다른 작품의 캐논, Storyyard 역수입본은 넣지 않는다. 첨부 파일 이름, Drive ID 또는 원천 경로, SHA-256, 채팅 URL이나 응답 식별자를 receipt에 남긴다.

SHA-256 권위는 로컬로 확보한 정확 사본에 `shasum -a 256`을 실행한 결과다. Web GPT Pro가 응답에서 스스로 말한 해시는 증거로 사용하지 않는다. 모델 해시가 로컬 해시와 달라도 본문 readback이 실제 파일과 일치하면 모델 해시만 비권위 관찰로 기록한다.

### 첨부 본문 접근 게이트

파일 이름이나 Drive ID가 응답에 보이는 것만으로는 첨부 성공으로 판정하지 않는다.

1. Web GPT Pro 채팅에 예정된 실제 파일 칩이 모두 붙었는지 확인한다.
2. readback에 담당 작품의 작품명, 현재 원고·State·Story Plan 식별 사실이 맞는지 확인한다.
3. 본 발주 전에 성공작 3개 각각에 대해 파일 내부의 구체 근거를 포함한 짧은 readback을 받는다.
4. Web GPT Pro가 파일 이름만 반복하거나 본문을 열 수 없거나 다른 작품을 전제로 답하면 Arc 생성을 요청하지 않는다.
5. 실패 원응답과 receipt를 먼저 보존하고, 첨부를 바로잡은 독립 채팅에서 정확히 한 번만 복구 발주한다.
6. 복구 readback도 실패하면 blocker로 종료한다.

1. `/Users/a2501/Desktop/v3_firefly_studio/.hermes/source-cache/drive/`의 검증된 정확 사본을 찾는다.
2. 없으면 `/Users/a2501/Desktop/ff_studio_v2`와 그 edge repo에서 같은 원문을 읽기 전용으로 찾는다.

## 4. 브라우저와 병렬 처리

- 모든 에이전트 브라우저 작업은 Chrome Beta의 `GPT-Agent` 프로필만 사용한다.
- 일반 Google Chrome은 사용자 전용이다. 에이전트는 열기, 종료, 탭 조작을 모두 하지 않는다.
- 작품별 Web GPT Pro 채팅과 응답 대기는 병렬 실행할 수 있다.
- 각 작품 세션은 전송 직전에 현재 선택된 활성 채팅의 정확한 작품명, 채팅 제목·URL, 파일 칩을 다시 확인한다.
- 사이드바 목록이나 비활성 탭에 다른 작품 대화가 존재하거나 제목이 보이는 것만으로는 오염 또는 blocker로 판정하지 않는다.
- 현재 선택된 활성 채팅의 본문·첨부 칩·응답에 다른 작품명, 원고, State, Plan이 섞였을 때만 전송·수용을 중단하고 오염 응답으로 보존한다.
- macOS Save/Open, 파일 선택기, 다운로드, 첨부, 제출처럼 Chrome Beta 전체에 영향을 주는 네이티브 UI 구간은 전역 임계 구간이다.
- 네이티브 UI 구간은 한 번에 작품 세션 하나만 사용한다. 완료 즉시 다음 세션에 넘긴다.
- 저장창이나 다운로드 자체는 blocker가 아니다. 인증, 권한 거부, 원문 부재, 검증된 다운로드 실패만 blocker다.
- 네이티브 저장창은 세션 종료 전에 반드시 처리한다. 필요한 새 원문이면 공용 cache에 저장하고 파일·해시를 검증하며, 이미 같은 정확본이 있거나 중복 파일명이면 즉시 취소한다.
- Save/Open·파일 선택창을 화면에 남긴 채 heartbeat 대기, 턴 완료, blocker 보고를 하지 않는다.

## 5. Heartbeat

### 작품 세션

Web GPT Pro에 질문이나 발주를 보낼 때마다 즉시 5분 heartbeat를 시작한다.

- 같은 채팅을 5분마다 확인한다.
- 최초 발주 때 기록한 정확한 채팅 URL 또는 response ID만 다시 타게팅한다. 그
  세션의 대화 기억을 후보 작성·검토·receipt 완료까지 이어 쓰며, 유사 제목의 새
  채팅이나 검색 결과를 대체 대상으로 쓰지 않는다.
- 완전한 응답 전에는 재촉하거나 중복 발주하지 않는다.
- 시각, 상태, 오류, 로그인·첨부 상태를 receipt에 기록한다.
- 응답 수집, 원문 보존, 제안 검토가 끝나기 전에는 세션 턴을 완료하지 않는다.

정확한 세션 식별자를 확인할 수 없으면 `Review`로 멈춘다. 자동화는 새 채팅을
열거나 이전 작업을 다른 채팅으로 복제하지 않는다. 새 채팅은 owner가 별도
dispatch로 승인한 경우에만 사용한다.

Sentinel의 `wgp_wait`는 이 대기 기록을 보조할 수 있다. 단, 로컬에 저장될
receipt의 존재와 해시·front matter만 확인하는 watch-only 작업이다. Web GPT Pro
UI를 열거나 재촉·재발주하지 않으며, deadline 초과는 owner `Review`로 올린다.

### 총괄 세션

총괄은 작품 세션 5개를 3분마다 한 번에 확인한다.

- 완료, 조기 종료, 권한 요청, 브라우저 충돌은 3분을 기다리지 않고 즉시 처리한다.
- `heartbeat active`라고만 보고하고 턴을 끝낸 작품 세션은 다시 깨워 실제 응답 완료까지 감시시킨다.
- 내용 작업에 개입하지 않고 lane, 진행, blocker, receipt 완결성만 관리한다.

## 6. Arc 요청 계약

- 작품 목표 길이: 250화.
- 회차 원고 본문: 공백 포함 4,000자 이상, 8,000자 이하.
- 글자 수에서는 제목, front matter·메타데이터, receipt, 장면 전환·제어 기호를 제외한다.
- Story Arc(B): 승인 원고 기준 1~5화.
- 기본 페이싱 기준: 약 3화. 성공작 3개의 실제 리듬에 따라 1~5화를 가변 적용한다.
- B001~B005가 덜 확정된 작품은 중심 질문, 압력, 비가역 결산, 보상, 다음 비용까지 구체화한다.
- `ep250`은 장기 완결 목표다. 250화 분량의 B 슬롯을 선작성하지 않고, 현재
  owner-approved 10-Arc batch만 내구 가설로 유지한다.
- B006 이후는 기능, 보상 축, 독자 부채, Anchor 연결 수준의 가설 슬롯으로 둔다. 미래의 정확한 사건, 숫자, 음식, 장면은 미리 잠그지 않는다.
- 각 B 종결 뒤 승인 원고의 실제 결과로 A-Rail과 남은 B-Rail을 reflow하고,
  B010 closeout 전 다음 10-Arc batch를 owner review로 연다.
- Web GPT Pro의 결과는 제안 후보다. owner 승인 전에는 캐논 파일에 반영하지 않는다.

## 7. 원고 조판 계약

- 지문 다음 지문: 줄바꿈은 유지하고 빈 줄은 넣지 않는다.
- 대사 다음 대사: 줄바꿈은 유지하고 빈 줄은 넣지 않는다.
- 지문과 대사 사이: 빈 줄 1개.
- 효과음: 앞뒤 빈 줄 1개의 독립 블록.
- 심리대사: 앞뒤 빈 줄 1개의 독립 블록.
- 과거·회상 대사: 지문과 앞뒤 빈 줄 1개.
- 제목, 소제목, `//-약속.` 같은 구획 표식: 본문과 빈 줄 1개.
- Web GPT Pro 원고 제작 발주와 Markdown 원고 후보의 장면 전환: 앞뒤 빈 줄 1개를 둔 단독 `◆ ◆ ◆`.
- 단독 `###`는 Markdown의 3단계 제목 문법이므로 원고 제작 발주에서 사용하지 않는다. 별도의 최종 TXT 산출이 필요할 때만 운반·조판 레인이 검증된 `◆ ◆ ◆`를 단독 `###`로 변환한다.

## 8. 작품 세션 시작 프롬프트

아래 대괄호 항목만 작품별 실제 값으로 바꿔 사용한다.

> 당신은 v3 Firefly Foundry의 작품별 상주 운영 세션이며 담당 작품은 `[작품명]` (`[work_slug]`) 하나뿐이다. 모델은 Codex Desktop `gpt-5.6-terra`, 중간이다.
>
> 루트와 Foundry의 `AGENTS.md`, Charter, Anchored Story Loop, Terminology, 작품 `00_status.md`를 먼저 읽고 실제 Git root와 승인 상태를 확인하라. v2는 원문 정확 사본 검색에만 읽기 전용으로 사용한다.
>
> 유사 성공작 3개를 Drive 원문 라이브러리에서 선별하고, 검증된 로컬 사본이 없을 때는 적극적으로 다운로드하라. 선택 이유, Drive ID 또는 원천 경로, 파일명, SHA-256을 기록하라.
>
> 성공작 3개, 현재 owner-approved 원고, Narrative State, Story Plan 네 표면을 Web GPT Pro의 작품별 독립 채팅에 첨부하라. 250화 목표, 1~5화 가변 Arc, 약 3화 기본 리듬, B001~B005 구체화, 약 B084까지의 장기 용량 가설, Arc 종결 후 reflow를 요청하라.
>
> 각 회차 원고 본문은 공백 포함 4,000~8,000자로 설계하라. 제목, 메타데이터, receipt, 장면 전환·제어 기호는 글자 수에서 제외한다.
>
> 본 발주 전 실제 파일 칩을 확인하고, 성공작 3개 각각의 본문 내부 근거를 포함한 readback을 받아 첨부 본문 접근을 증명하라. 파일명 반복은 통과가 아니다.
>
> 질문이나 발주 직후 5분 heartbeat를 실제로 시작하고 완전 응답을 보존·검토할 때까지 턴을 끝내지 마라. 브라우저는 Chrome Beta만 사용하고 네이티브 UI 구간만 다른 작품 세션과 순차 처리하라.
>
> Web GPT Pro 원응답과 검토 제안을 분리해 저장하라. 캐논 수정, owner 승인 표기, Storyyard 전송, 공개, 커밋, 푸시는 하지 마라. 완료 시 산출물 경로와 blocker만 보고하라.

## 9. 완료 조건

- 성공작 3개의 접근·선정·해시 증거가 있다.
- receipt의 해시는 모델 진술이 아니라 로컬 정확 사본의 계산값이다.
- 실제 파일 칩과 성공작별 본문 근거 readback으로 첨부 접근이 증명됐다.
- 현재 승인 원고와 Story Plan 정확본만 첨부됐다.
- Web GPT Pro 채팅·첨부·heartbeat receipt가 있다.
- Arc 제안과 향후 원고 발주가 회차당 공백 포함 4,000~8,000자 계약을 반영한다.
- Web GPT Pro 원응답이 변경 없이 보존됐다.
- 별도 검토 제안이 있다.
- 캐논, Storyyard, Git에는 owner 미승인 변경이 없다.

추후 자동화는 원문 탐색, 공용 캐시, 패킷 조립, 첨부, heartbeat, receipt, 감리 패킷 생성까지를 대상으로 한다. 최종 판정과 캐논 승격은 자동화하지 않는다.
